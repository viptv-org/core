# Android transport

Include `src/main/kotlin` in the native Android shell source set. This adapter uses Android's built-in `org.json` and OkHttp. The Android app pins OkHttp 4.12.0; the adapter uses the compatible okhttp3 API. Declare `android.permission.INTERNET`. Supply a bounded background executor and exact authorized backend origins. The shell owns that executor and shuts it down when appropriate.

Android mobile SmartCast support uses `SmartCastClient`, `SmartCastTransport`, and `SmartCastTokenStore`. The client drives the native Rust `SmartCastBridge` until a command completes, so UI code never interprets SmartCast responses or provides firmware hash values. `SmartCastTransport` is a separate OkHttp client that accepts a television's self-signed certificate only after checking every request against the selected HTTPS host and port; redirects and automatic retries are disabled. `SmartCastTokenStore` encrypts each bearer token with a non-exportable Android Keystore AES-GCM key. Do not share this client or TLS policy with backend, artwork, catalog, or media requests.

The mobile app must supply a stable random `deviceId` across pairing attempts, persist only the encrypted token, and treat final `result` objects as the UI-facing response. Pairing PINs remain transient. Closing or changing TVs cancels the in-flight request and bridge workflow. Android TV adoption is outside the current SmartCast product scope.

For each `{id,effect:{Http:request}}` returned by the native Rust bridge, call `execute(JSONObject(requestJson))`, then pass the callback's JSON to `core.resolve(id, result.toString())` on the core owner's thread. Forward resulting effects through the same dispatcher. Retain the returned `Call` and cancel it on teardown or scope changes. The Rust core also discards stale results by epoch. Do not instantiate WASM on Android.

Responses preserve binary bytes as unsigned JSON numbers, duplicate header values, and all HTTP statuses (including 4xx/5xx) as `Ok`. Redirects are disabled before networking; URL credentials and origins outside the configured set are rejected. Cancellation, size-limit failures and sanitized IO errors resolve once as `Err.Io`; socket timeouts resolve as `Err.Timeout`. OkHttp call timeout bounds the complete exchange, in addition to connect/read limits. Automatic retries are disabled so mutation retry policy stays in the core. Android's network security policy controls any explicitly authorized cleartext development origin.

PATCH and empty POST/PUT/PATCH bodies are supported. The Android app includes this adapter for the actual Crux session effect loop. Its hosted review compiles the native core, generated Kotlin and application together. Refer to Android TESTING.md for the latest compilation/device evidence; this source alone does not establish hardware qualification.
