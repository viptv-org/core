# Browser build boundary

This package compiles `../crates/viptv-core/src/lib.rs` directly. It has no copied application policy or separate Rust implementation. Native-only engine/SDK, UUID and keyring dependencies are absent from browser resolution; the native workspace and its lockfile remain unchanged. The browser lock pins wasm-bindgen 0.2.92 and js-sys/web-sys 0.3.69 so the generated JS uses the compatible heap shim rather than externref.

Run `bash scripts/build-wasm.sh` from the repository. It requires wasm-bindgen-cli 0.2.92 (or an explicit matching `VIPTV_WASM_BINDGEN` executable), uses this package's locked graph and writes the ordinary `generated/wasm` files. `.cargo/config.toml` continues disabling reference types. Native build outputs under `generated/android` are ignored; committed source/generated interface files remain authoritative.

`bash scripts/test-wasm-features.sh` validates the actual module against an explicit MVP plus mutable globals, saturating float-to-int, sign extension, multi-value and bulk-memory ceiling. It excludes reference types, SIMD, WasmGC, typed function references, multi-memory, memory64, exceptions, tail calls and threads. This is a module validation gate, not a claim about every television firmware.

This boundary matters: [V8 9.6 shipped reference types with Chrome 96](https://v8.dev/blog/v8-release-96); Chrome87 cannot be assumed to support externref. The [WebAssembly project's engine feature matrix](https://github.com/WebAssembly/website/blob/main/features.json) distinguishes those features from multi-value (Chrome85), bulk memory (Chrome75), and SIMD (Chrome91). Do not equate WebAssembly reference types with ordinary JavaScript garbage collection or the newer WasmGC proposal.

Qualification instantiated the regenerated module with the checksum-verified official Node15.14.0 binary's V8 8.6.395.17, running all 100 playback/request vectors and three shared startup vectors. V8 identifies [8.6 as the Chrome86 generation](https://v8.dev/blog/v8-release-86). Reproduce with that engine and `node scripts/test-wasm-compat.mjs`; installation of an obsolete Node is isolated test tooling, not a server/runtime dependency. The explicit offset vectors preserve HLS48.6s, reject double-seek/negative clocks, and preserve original MP4 zero-offset seeking. Full actual-WASM/native policy, runtime and authority parity checks also pass on current Node. Device DOM/player behavior remains a separate consumer check.
