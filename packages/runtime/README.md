# Crux shell HTTP runtime

`createHttpTransport` executes official `crux_http` 0.20 JSON requests and returns its JSON `HttpResult`. Protocol types import Rust-generated `generated/typescript/wire.ts`, which describes the exact Serde JSON bridge representation. No HTTP fields or variants are redefined by the adapter. The caller owns the effect ID; pass `JSON.stringify(result)` to the same core instance's `resolve(id, ...)`, then dispatch the returned effects. All HTTP statuses, including 4xx/5xx, are `Ok` exchanges. Browser-visible response headers are subject to CORS and Fetch's header normalization. Bodies remain bytes, including error bodies. This adapter contains no endpoint, account, navigation or playback rules.

Browser: instantiate the WASM core and use `createHttpTransport({allowedOrigins: [backendOrigin], credentials: 'include'})` when cookie authentication is required. Credential mode defaults to `omit`; native token headers come from the core. Fetch is injectable for host integration and validation.

Tauri: instantiate the **native Rust core** in the host; expose update/resolve/view through Tauri commands. Import `createTauriHttpTransport` from `@viptv/core-runtime/tauri` to execute emitted HTTP effects using `@tauri-apps/plugin-http` 2.6.0. Register `tauri_plugin_http::init()` in the host and grant `http:default` with exact URL scopes in the Tauri capability file. The plugin fetch uses native Rust HTTP, and `maxRedirections: 0` is mandatory in addition to Fetch's redirect setting. The Tauri shell does not load the browser WASM core. Actual host registration/packaging belongs to the consuming application.

Each call accepts an AbortSignal. Shells abort active effects on disposal/scope changes and still resolve their sanitized cancellation output; Rust's epoch checks prevent stale state transitions. URL credentials, fragments and non-allowlisted origins are rejected. Redirects are never followed, preventing cross-origin credential forwarding. Configure exact development origins explicitly. Responses are bounded to 8 MiB by default and a 30-second deadline covers fetch and body reads. No raw transport exception or request is logged.

Authoritative verification: [crux_http protocol](https://docs.rs/crux_http/0.20.0/crux_http/protocol/index.html), [Crux bridge](https://docs.rs/crux_core/0.20.0/crux_core/bridge/index.html), [Tauri HTTP plugin](https://v2.tauri.app/plugin/http/). Published versions were checked against the crates sparse index and npm registry. Neither package installation nor hardware qualification is implied by registry availability.

The `./driver` export provides `createCoreDriver({core, storage, http, render, onError})`. Pass the browser's WASM `CoreBridge` directly as `core`, or `tauriCorePort(invoke)` for native commands. Storage implements `load`, `save`, and `clear` using platform secure persistence. The driver dispatches generated event JSON, correlates every effect result, serializes core entry and storage writes, drains subsequent effects and reads the view on Render. HTTP runs concurrently up to the configured pending-effect bound (64 by default). Call `cancelHttp()` when changing scope and `dispose()` on shell teardown; disposal aborts network work and suppresses later core/view updates. Already-issued storage writes may finish, so durable state changes remain core-controlled. `idle()` waits for drained work for validation. Existing pairing UI can dispatch `AdoptSession` after successful pairing; it must not duplicate restoration or refresh decisions.

After implementation completion, `npm test` uses Node 22's type stripping to exercise the injectable HTTP and driver boundaries without a browser, Tauri process or live credentials. Native-fetch tests verify the Tauri-specific redirect option; they do not claim real plugin IPC or device qualification. Type-check consuming code with TypeScript's `allowImportingTsExtensions` and `noEmit` (or a bundler supporting TypeScript source exports).
